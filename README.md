# Migration Tool & AI

This project provides tooling to **analyze**, **scan**, and **validate** Java applications targeted for migration — primarily from Spring Boot to Quarkus. It exposes its capabilities as a [Quarkus MCP server](./mcp), enabling AI agents to leverage the tool's analysis and validation features through the [Model Context Protocol](https://modelcontextprotocol.io/). While the architecture is designed to support migration from any technology A to B, the current focus is Spring Boot to Quarkus.

## Dictionary

- **Query**: A simplified syntax (parsed using [Antlr](https://www.antlr.org/) grammar) to define matching conditions with `AND` / `OR` operators against Java annotations, POM dependencies, properties, etc. The query language could be extended in a future release to configure validators using YAML specifications.
- **Validator**: A validator verifies whether specific migration conditions are met for a given project (e.g. project setup, persistence layer). Validators are discovered at runtime from the classpath and can be invoked via the CLI or the MCP server.
- **Analysis report**: The analysis report generated by the rule engine contains issues describing what the tool or user should do, when it should be applied and for which purpose.

- **MCP Server**: A [Quarkus MCP server](./mcp) that exposes the tool's analyze and validate capabilities as MCP tools, allowing AI agents to interact with the migration tool programmatically.

- **Provider**: A system able to execute the transformation instructions defined as part of a rule where the condition(s) matched. Supported providers: [OpenRewrite recipe](https://docs.openrewrite.org/recipes) and manual.
- **Rule**: A rule defines what the tool should search for within the code source of the scanned project (matching conditions) and optionally includes instructions to be executed by a provider during transformation. Rules are defined in YAML and could be used in a future release to configure validators and define migration plans.

## Design & Components

The project uses the [Spring TODO](./applications/spring-boot-todo-app) example as the Java project to be analyzed using augmented [rules](./cookbook/rules).

The project has been designed using the following technology:
- [Quarkus and Picocli](https://quarkus.io/guides/picocli) to manage the CLI part and commands
- [Quarkus MCP server](./mcp) to expose analyze and validate tools to AI agents
- [OpenRewrite recipe](https://docs.openrewrite.org/concepts-and-explanations/recipes) to execute the transformations as defined in the rule's instructions
- [Antlr](https://www.antlr.org/) as parser tool to generate the code for the Query language used to `match` conditions
- [Tree-sitter](https://tree-sitter.github.io/tree-sitter/) for fast, accurate Java source code analysis
- The different applications: `mvn command` are executed as OS processes using Java `ProcessBuilder`

## Requirements

- Java 21 installed and Maven 3.9

## Setup

Install the tool using the [jbang](https://jbang.dev) tool and the following command:
```shell
jbang app install mtool@snowdrop/migration-tool
```

> [!NOTE]
> To install a released version, append the version
```shell
jbang app install mtool@snowdrop/migration-tool/2.0.0
```

Otherwise, if you plan to contribute to the project, git clone and compile it

```shell
mvn clean install -DskipTests
```

## AI — MCP Server

The migration tool includes a [Quarkus MCP server](./mcp) that exposes its different capabilities (analyze, validate, ...) as MCP tools. AI agents can use these tools to programmatically analyze source code, discover annotations/dependencies, and validate migration correctness.

### Install the ACP client

Before using the MCP server with an AI agent, we recommend locally to use and install the [Smallrye ACP client](https://github.com/smallrye/smallrye-ai) (>= 0.2.1) as you will be able to use your favorite agent and launch the MCP server with just a few parameters:
```shell
jbang app install --name acp io.smallrye.ai:acp-java-client:0.2.1:runner
```

Install an AI agent from the [ACP registry](https://agentclientprotocol.com/get-started/registry):
```shell
acp registry install claude-acp
```
**Note**: Use the command `acp registry list -r` to get the full list of ACP agents !

### Build the MCP server

```shell
mvn package -pl mcp
```

### Analyze with an AI agent

Run the MCP server in stdio mode and ask the agent to analyze a project:
```shell
acp run \
  -a claude-acp \
  --backup no \
  --mcp-server-config '{"type":"stdio","name":"mtools","command":"java","args":["-jar", "./mcp/target/mcp-2.0.0-SNAPSHOT-runner.jar"]}' \
  -p "The Project path of the code to analyze using the MCP tool: sourceAnalyze is: ./applications/spring-boot-todo-app"
```

### Validate with an AI agent

Run the validate tool to check that a migration from Spring to Quarkus is correct:
```shell
acp run \
  -a claude-acp \
  --backup no \
  -s ./mcp/skills/validate/SKILLS.md \
  --mcp-server-config '{"type":"stdio","name":"mtools","command":"java","args":["-jar", "./mcp/target/mcp-2.0.0-SNAPSHOT-runner.jar"]}' \
  -p "Validate the migration of the spring project: ./applications/spring-jpa-crud against the quarkus project: ./applications/spring-jpa-crud-quarkus. Only run the validator: persistence"
```

### Filesystem access guardrail

The MCP server restricts tool access to a set of allowed directories, following the [MCP local server security](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/local-server-security#limit-filesystem-access) convention. By default, the current working directory (`.`) is allowed. Override with `-Dmtool.allowed-dirs`:

```shell
--mcp-server-config '{"type":"stdio","name":"mtools","command":"java","args":["-Dmtool.allowed-dirs=./applications,/tmp/projects", "-jar", "./mcp/target/mcp-2.0.0-SNAPSHOT-runner.jar"]}'
```

## Client commands

The Migration Tool CLI (aka `mtool`) proposes the following commands:

```shell
Usage: mtool [-hV] [COMMAND]
Quarkus mtool client able to scan, analyze and migrate a java application
  -h, --help      Show this help message and exit.
  -V, --version   Print version information and exit.
Commands:
  analyze    Analyze a project for migration
  validate   Validate that a migration is correct and complete
  scan       Scan an application against a query
  transform  Transform a java application
  help       Display help information about the specified command
```

To check the installed version:
```shell
mtool --version
```

### Analyze

Scan the code source using the rules matching conditions and generate a JSON report augmented with the provider's instructions.

```shell
Usage: mtool analyze [-v] [-o=<output>] [-r=<rulesPath>] [-s=<source>]
                   [--scanner=<scanner>] [-t=<target>] <appPath>
Analyze a project for migration
      <appPath>             Path to the Java project to analyze
  -o, --output=<output>     Export the analysing result using the format.
                              Values: json
  -r, --rules=<rulesPath>   Path to rules directory (default: from config)
  -s, --source=<source>     Source technology to consider for analysis
      --scanner=<scanner>   Scanner tool to be used to analyse the code:
                              openrewrite (default)
  -t, --target=<target>     Target technology to consider for analysis
  -v, --verbose             Enable verbose output
```

Example:
```shell
mtool analyze ../applications/spring-boot-todo-app
mvn -pl migration-cli quarkus:dev -Dquarkus.args="analyze ../applications/spring-boot-todo-app"
```

By default, the tool generates a JSON report file: `analysing-report_yyyy-mm-dd_hh:mm.json`. Use `-o html` for HTML output.

#### Scanner

The tool supports different scanners:
- openrewrite recipe (default)
- treesitter
- maven
- file and content search

A scanner can be selected with the `--scanner` option. The tool will use it as default but will fall back to alternative scanners if the selected one doesn't support the query type.

### Validate

Validate that a Spring-to-Quarkus migration is correct and complete. Available validators:

- **project-setup** — checks that the project compiles and has the expected structure
- **persistence** — compares JPA entities between the original Spring project and the migrated Quarkus project to detect missing entities, field mismatches, ID strategy changes, and relationship differences

```shell
Usage: mtool validate [-v] [--skip-compile] [--parser=<parser>]
                      [--spring-project=<springProjectPath>]
                      <validatorName> <appPath>
Validate that a migration is correct and complete
      <validatorName>       Validator to run (e.g. project-setup, persistence)
      <appPath>             Path to the project to validate
      --parser=<parser>     Java parser to use: treesitter (default) or javaparser
      --skip-compile        Skip the mvn compile check
      --spring-project=<springProjectPath>
                            Path to the original Spring project
                              (required for persistence validator)
  -v, --verbose             Enable verbose output
```

Example:
```shell
mtool validate persistence ./applications/spring-jpa-crud-quarkus --spring-project ./applications/spring-jpa-crud
```

### Scan a project using query

Execute a query against an application to search for Java annotations, POM dependencies, properties, etc.

```shell
mtool scan <appPath> <query>
```

Using queries:
```shell
java.annotation is 'org.springframework.boot.autoconfigure.SpringBootApplication'
pom.dependency is (gavs='org.springframework.boot:spring-boot-starter-web')
```

You can also combine queries in a YAML plan file:
```shell
mtool scan <appPath> --plan <planPath>/java-app.yml --scanner treesitter
```

Example YAML plan:
```yaml
name: java-application
queries:
  - find all java.class
  - find all java.annotation
  - find all java.import
  - find all properties
  - find all pom.dependencies
```

### Transform

Apply the transformation instructions using as input the JSON analysis report by using the chosen provider.

```shell
Usage: mtool transform [-dv] [-p=<provider>] <appPath>
Transform a java application
      <appPath>   Path to the Java project to transform
  -d, --dry-run   Execute OpenRewrite in dry-run mode (preview changes without
                    applying them)
  -p, --provider=<provider>
                  Migration provider to use (openrewrite, manual). Default:
                    from migration.provider property
  -v, --verbose   Enable verbose output
```

> [!NOTE]
> The default provider is `openrewrite` but you can also use `manual`

#### Rule definition

A rule defines the contract between what to discover in the code source and what a provider should do to transform it. Key fields:

- `order`: The execution order within the migration plan
- `when`: Matching conditions using the query language
- `precondition`: Eligibility check before the main conditions are evaluated
- `instructions`: Tasks to be executed by the selected provider

```yaml
- ruleID: springboot-annotations-to-quarkus-00000
  category: mandatory
  description: Replace the Spring Boot Application Annotation with QuarkusMain
  labels:
    - source=springboot
    - target=quarkus
  message: "Replace the Spring Boot Application Annotation with QuarkusMain"
  when:
    precondition: |
      pom.dependency is (gavs='org.springframework.boot:spring-boot-starter-parent:3.5.3')
    condition: |
      java.annotation is 'org.springframework.boot.autoconfigure.SpringBootApplication'
  order: 2
  instructions:
    manual:
      - todo: "Remove the @SpringBootApplication annotation from the main class"
    openrewrite:
      - name: Migrate Spring Boot to Quarkus
        preconditions:
          - name: org.openrewrite.java.dependencies.search.ModuleHasDependency
            groupIdPattern: org.springframework.boot
            artifactIdPattern: spring-boot
            version: '[3.5,)'
        recipeList:
          - dev.snowdrop.mtool.openrewrite.recipe.ReplaceSpringBootApplicationAnnotationWithQuarkusMain
          - spring.recipe.dev.snowdrop.mtool.openrewrite.AddQuarkusRun
        gav:
          - dev.snowdrop.mtool:openrewrite-recipes:2.0.0-SNAPSHOT
```

#### Query language

The query language is defined using an Antlr grammar and supports simple clauses or multiple clauses separated with `AND` / `OR` operators:

```g4
grammar Query;

searchQuery: operation;
operation
    : operation AND operation #AndOperation
    | operation OR operation  #OrOperation
    | clause                  #SimpleClause
    ;

clause: fileType ('.' symbol)? ('is' | '=') (value | '(' keyValuePair (',' keyValuePair)* ')');
fileType: 'JAVA' | 'java' | 'POM' | 'pom' | 'TEXT' | 'text' | 'PROPERTY' | 'property' | 'YAML' | 'yaml' | 'JSON' | 'json';
```

Examples:
```yaml
when:
  condition: java.annotation is 'org.springframework.boot.autoconfigure.SpringBootApplication'
  condition: |
    java.annotation is 'org.springframework.stereotype.Controller' OR
    java.annotation is 'org.springframework.web.bind.annotation.GetMapping'
  condition: |
    pom.dependency is (gavs='org.springframework.boot:spring-boot-starter-web') AND
    java.annotation is 'org.springframework.stereotype.Controller'
```

#### Transform with OpenRewrite

To use OpenRewrite, execute the transform command with or without `--dry-run` mode. In dry-run mode, OpenRewrite generates `rewrite.patch` file(s) under `target/rewrite` instead of modifying the code directly.

```shell
mtool transform ../applications/spring-boot-todo-app -p openrewrite --dry-run
```

#### Example: Spring Boot Todo to Quarkus

Migrate the [Spring Boot Todo Application](applications/spring-boot-todo-app) to Quarkus step by step.

Git clone this project and compile it:
```shell
mvn clean package -DskipTests
```

1. **Analyze** the project to generate the migration report:
```shell
mtool analyze ../applications/spring-boot-todo-app -r ../cookbook/rules/quarkus-spring --scanner openrewrite
```

2. **Preview** the transformation (dry-run mode):
```shell
mtool transform ../applications/spring-boot-todo-app -p openrewrite --dry-run
```

3. **Apply** the transformation:
```shell
mtool transform ../applications/spring-boot-todo-app -p openrewrite
```

> [!NOTE]
> We recommend creating a git branch within the "spring-boot-todo-app" to revert to the previous state if needed

4. **Run** the migrated Quarkus application:
```shell
cd applications/spring-boot-todo-app
mvn package quarkus:dev -DskipTests
```

> [!NOTE]
> Podman or Docker must be installed locally as Quarkus will launch a MySQL TestContainer for the Todo DB.

5. **Test** the REST endpoints:
```shell
curl http://127.0.0.1:8080/home

curl -X POST http://localhost:8080/home \
-H "Content-Type: application/json" \
-d '{
"title": "Prepare migration to Quarkus. Step 3",
"description": "Analyser le projet et lister toutes les dependances Spring Data.",
"dueDate": "2025-12-24"
}'
```

## Tips

The `analyze` or `transform` commands can be executed using the Quarkus uber jar. Create an `.env` file to configure the properties:

```properties
# .env file content
ANALYZER_RULES_PATH=cookbook/rules
```

Then source it and execute:
```shell
java -jar <MIGRATION_CLI_JAR_PATH> analyze $(pwd)/applications/spring-boot-todo-app -o json
java -jar <MIGRATION_CLI_JAR_PATH> transform $(pwd)/applications/spring-boot-todo-app -p openrewrite --dry-run
```

To test OpenRewrite recipes separately, use the [maven plugin](https://docs.openrewrite.org/reference/rewrite-maven-plugin) on a Spring Boot project:
```shell
cd applications/spring-boot-todo-app
mvn -U org.openrewrite.maven:rewrite-maven-plugin:dryRun \
   -Drewrite.recipeArtifactCoordinates=dev.snowdrop.mtool:openrewrite-recipes:2.0.0-SNAPSHOT \
   -Drewrite.activeRecipes=spring.recipe.dev.snowdrop.mtool.openrewrite.ReplaceSpringBootApplicationWithQuarkusMainAnnotation
```
